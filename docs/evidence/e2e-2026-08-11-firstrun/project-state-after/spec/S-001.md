# Spec: Email address validation
status: ratified
authored: drafted

## Goal

Provide a public utility that determines whether a supplied string has a practical, commonly accepted email-address format.

## Non-goals

- Does not verify that the address, domain, or mailbox actually exists.
- Does not send a verification email or contact an external service.

## Acceptance criteria

- Common addresses such as user@example.com and first.last+tag@example.co.uk are accepted.
- Malformed values such as missing an @ sign, missing a local part or domain, containing spaces, or having an incomplete domain are rejected.
- Non-string, empty, and whitespace-only values are rejected without throwing an unexpected error.
- The validator is available through the package's public interface.
- Running npm test completes successfully with tests covering accepted and rejected examples.

## Assumptions

- Validation returns a boolean rather than throwing for invalid input.
- Validation checks practical syntax suitable for ordinary application input rather than implementing every address permitted by the full email RFCs.
- Leading or trailing whitespace makes the supplied value invalid rather than being silently removed.
