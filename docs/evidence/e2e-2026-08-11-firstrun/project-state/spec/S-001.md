# Spec: Email address validation
status: draft
authored: drafted

## Goal

Provide a reusable way to determine whether a supplied value is a valid email address and return a clear valid-or-invalid result.

## Non-goals

- Does not verify that an email address exists, can receive mail, or belongs to the person entering it.

## Acceptance criteria

- A person can validate an ordinary address such as "person@example.com" and receive a valid result.
- Malformed values such as "person@", "@example.com", and non-string inputs receive an invalid result without crashing.
- The validation behavior is documented with examples.
- Running "npm test" completes successfully and includes passing tests for representative valid, invalid, and non-string inputs.

## Open questions

- Should validation check only practical email syntax, or must it support the full range of addresses permitted by email standards?

## What was asked for

Add a way to validate email addresses
