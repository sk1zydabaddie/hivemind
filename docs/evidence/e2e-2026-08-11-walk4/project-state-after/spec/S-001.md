# Spec: Email address validation
status: ratified
authored: drafted

## Goal

Provide a reusable way to determine whether a value is a plausibly valid email address. Validation should return a clear valid-or-invalid result without contacting external services.

## Non-goals

- Does not verify that the domain or mailbox exists or can receive email.

## Acceptance criteria

- Run `npm test` and confirm all tests pass.
- Common addresses such as `person@example.com` are accepted.
- Malformed values such as `person`, `@example.com`, `person@`, whitespace-only strings, and non-string values are rejected without throwing an error.

## Assumptions

- Validation uses practical email syntax rules rather than attempting complete RFC compliance.
- Leading or trailing whitespace makes an address invalid rather than being removed automatically.
- The validator returns a boolean result.
